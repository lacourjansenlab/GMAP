Useful resources#

These resources might come in handy while writing code/documentation for this project.

Sources for writing documentation#

Installation#

Installing all programs to create the documentation might be confusing. Besides the installation instructions in this project’s README.md, you might also want to check out the following resources:

  • Installing sphinx from the Sphinx main documentation pages provides many different ways of installing sphinx besides pip install.

  • Getting started from the numpydoc pages explains how to install it, and gives some possible flags to use in the sphinx conf.py.

  • Napoleon is another tool that can be used for reading numpydoc-style docstrings, I haven’t used it yet at the time of writing this.

  • The sphinx autodoc tutorial for dummies might be ancient and written for python 2.7, it still gives a good overview of the steps required. Many details, however, are not accurate anymore.

  • Sphinx and numpydoc is the followup to the autodoc tutorial for dummies. Same warnings apply!

  • On the sphinx theme gallery page you can find many more themes to render documentation in.

  • Sphinx-design allows the use of more complex structures in the pages.

Setting up#

After installation, Sphinx needs to be configured. Here are some useful pages on how to configure different parts/tools.

  • Configuration from the sphinx documentation pages lists many possible options/settings for the sphinx conf.py file.

  • Autodoc is the tool used for automatically retrieving docstrings from python code.

  • Sphinx apidoc can take additional commands .

Writing documentation#

At some point the documentation itself has to be written. reST and numpydoc have their own syntax, here are some pages to help with that.

  • Cheat sheets are always the best!

  • Directives automatially create text with a special format. There are many available options - a good example is the ‘see also’ section that exists on most numpy pages. Example

  • Numpydoc has written a cohesive style guide which explains how each section of a docstring should be used, but doesn’t explain much on how to actually do many things.

  • In addition to the previous point, sphinx has some very good examples of docstrings.

  • This and this stackoverflow question both have some very clear answers on how to link to code objects, both from within docstrings, and in other documentation pages like this one.

  • In addition to the previous point, here is an overview on what flags for python objects are available besides those mentioned in the stackoverflow answers.

  • General cross-references are explained here , this is mainly useful to linking to pages like this.

  • Although a very niche problem, this solution for when sphinx throws an error related to unordered list within python docstrings. The error text is not very clear, you have to recognize the error by knowing the function that throws the error has an unordered list.

  • This stackoverflow question has some useful answers on how to add website hyperlinks in your documentation pages. Or you just check out the source of this page for plenty of examples.

  • This is a good explanation on how to use (un)ordered (nested) lists in the documentation pages.

  • and this is a good example on how to mark headers.

  • The PyData Sphinx Theme page contains some cool inspiration for looks/layout/structure of webpage.

  • The current home page of the documentation contains a combination of grids and cards for a cleaner look.
